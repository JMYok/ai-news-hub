Router-R1: 强化学习多轮路由

机构: UIUC | 会议: NeurIPS 2025
代码: github.com/ulab-uiuc/Router-R1

🎯 解决的问题

现有路由器只能做单轮一对一分配，无法利用多模型协作。复杂任务需要多个模型配合，但传统方法无法动态调用和聚合。

💡 核心创新

  • 路由器本身是一个具备推理能力的LLM
  • 三种动作交替执行：Think → Route → Aggregate
  • 创新的Cost Reward实现性能-成本动态平衡
  • 基于简单模型描述符实现强泛化性

🏗️ 技术架构

奖励函数 = 格式奖励 + 结果奖励 + 成本奖励
Cost Reward = -α × (模型参数规模 × 输出Token数)

使用veRL框架 + GRPO方法训练，在7个QA基准上取得SOTA。

🔧 复现步骤

  1. 克隆代码仓库
  2. 准备候选模型描述符（价格、延迟、示例性能）
  3. 合并问答数据集
  4. 使用veRL框架进行GRPO训练（约100步收敛）
  5. 调整α参数控制性能-成本权衡

LLMRouter: 统一路由框架

机构: UIUC U Lab | 类型: 开源项目
代码: github.com/ulab-uiuc/LLMRouter

🎯 解决的问题

大模型应用面临"成本-质量"两难困境。用GPT-4太贵，用小模型质量差。需要智能调度员在成本和效果间找平衡。

💡 核心创新

  • 16+种内置路由算法（KNN、SVM、MLP、GNN、RL等）
  • 统一CLI：一行命令完成训练、推理、交互
  • 支持单轮/多轮/个性化/智能体路由
  • 插件系统支持自定义路由器

🏗️ 技术架构

四大路由类型:
单轮路由 → 多轮路由(Router-R1) → 个性化路由(GMTRouter) → 智能体路由

三大设计原则：稳定路由契约、决策与执行分离、配置驱动。

🔧 复现步骤

  1. conda create -n llmrouter python=3.10
  2. pip install -e .
  3. llmrouter train --router knnrouter
  4. llmrouter chat 启动交互界面
  5. 开发自定义路由器继承MetaRouter

GraphRouter: 图神经网络路由

机构: UIUC | 论文: arXiv:2410.03834
代码: github.com/ulab-uiuc/GraphRouter

🎯 解决的问题

LLM越来越多，如何为每个查询选择效果最佳且成本最低的模型？传统方法只选大小、不懂上下文、遇到新模型就懵。

💡 核心创新

  • 将任务-查询-LLM关系建模为异构图
  • 通过LLM文本描述（而非编号）表征模型
  • 实现新模型的零样本泛化
  • 一个模型支持多种任务类型

🏗️ 技术架构

三种节点: 任务节点 + 查询节点 + LLM节点
边预测: 计算查询-LLM匹配分数选择最优

相比现有方法提升12.3%，新LLM泛化场景下提升9.5%，时间成本降低99.45%。

🔧 复现步骤

  1. 安装PyTorch + PyTorch Geometric
  2. 使用GPT-4o生成LLM描述
  3. 构建异构图（任务+查询+LLM节点）
  4. 使用RoBERTa编码文本描述
  5. 最佳配置：2层GNN，隐藏维度32

RouterBench: 路由基准测试

机构: Martian + UC Berkeley | 论文: arXiv:2403.12031
代码: github.com/withmartian/routerbench

🎯 解决的问题

没有统一标准评估不同路由系统。就像比赛没有裁判和规则，大家各说各的。需要一个公平的"奥运会"来测试路由系统。

💡 核心创新

  • 构建40万+样本、11个模型、8个任务的大规模数据集
  • 提出AIQ (Average Improvement in Quality)评估指标
  • 设计成本-质量（c-q）平面理论框架
  • 测试预测式（KNN/MLP）和级联式两种路由策略

🏗️ 技术架构

核心发现:
理想路由器可用低成本达到接近GPT-4性能，实际可节省2-5倍成本

级联式路由在评判器准确时表现优异，但容错性较差。

🔧 复现步骤

  1. 克隆routerbench仓库
  2. 准备8个数据集（MMLU、GSM8K、MBPP等）
  3. 实现KNN路由（k=40, all-MiniLM-L12-v2）
  4. 实现级联路由（需要评判器）
  5. 计算AIQ指标进行公平比较

OmniRouter: 约束优化路由

机构: Rutgers University | 发表: ACM SIGKDD 2025
代码: github.com/dongyuanjushi/OmniRouter

🎯 解决的问题

传统路由采用贪心策略，逐个查询做局部最优决策，无法考虑全局预算约束。导致简单查询占用了强模型，复杂查询失败。

💡 核心创新

  • 两阶段架构：混合检索增强预测器 + 约束优化器
  • 将路由从贪心决策转变为约束优化问题
  • 拉格朗日对偶分解求解最优分配
  • 同时控制预算、性能、并发量

🏗️ 技术架构

阶段1: BERT编码 + 双头预测（能力+长度）
阶段2: 拉格朗日对偶分解优化

准确率提升最多6.30%，成本降低至少10.15%，在严格约束下表现更稳定。

🔧 复现步骤

  1. 准备MMLU/GPQA/MATH/GSM8K数据集
  2. 用10个候选模型生成回答
  3. 用Llama-3.1-70B评判正确性
  4. 训练BERT双头预测器
  5. 实现拉格朗日对偶优化器
