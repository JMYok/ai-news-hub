### Anthropic Engineering — Scaling Managed Agents: Decoupling the Brain from the Hands

Anthropic 发布了关于 Managed Agents 架构的深度技术文章，核心设计原则是**将 agent 的"大脑"（Claude + harness）与"双手"（沙盒、执行环境）解耦**。

**传统方案的缺陷**：将 harness、session、sandbox 放入单一容器，导致容器成为"宠物"——一旦失败，整个 session 丢失；调试只能通过 WebSocket 事件流，无法定位具体故障原因。

**解耦后的优势**：容器死亡被捕获为 tool-call 错误，harness 可重新初始化新容器；harness 本身也成为 stateless，可随时重启并通过 `getSession(id)` 恢复。

**安全边界**：token 永远不进入 sandbox（通过 vault 外置 + MCP proxy 隔离），解决了 prompt injection 后直接访问凭证的核心风险。

**性能提升**：解耦后 p50 TTFT 下降约 60%，p95 下降超过 90%。因为不需要等待容器初始化，inference 可在 orchestration 层从 session log 拉取 pending events 时立即开始。

**多脑多手**：支持单个 Claude 实例连接多个执行环境（通过 `execute(name, input) → string` 接口），实现了真正并行的多工具调用。

https://www.anthropic.com/engineering/managed-agents

### Training Data — "Rebuilding IT From the Ground Up for the AI Age: Serval's Jake Stauch"

Daytona CEO Ivan Burazin 在 MAD Podcast 上系统性地阐述了他对 AI Agent 基础设施的思考。他认为过去二十年所有人都在谈"本地开发环境末日"，但开发者说"除非从我冷冰冰的尸体上拿走我的 localhost"。直到 Agent 出现，情况才真正改变——因为 Agent 不需要在意在哪台机器上运行，它们只需要一台属于自己的电脑。

Burazin 将当前的 Agent 技术栈分为几层：模型（大脑）、工具（沙盒、电脑、MCP）、记忆（memory）和编排（orchestration）。其中记忆是当前最未被解决的难题——目前最佳方案是用 Markdown 文件，但模型本身并不会在学习中真正变聪明，每次都是"新模型"而不是"更好的模型"。

他还提到了一个重要预测：继 GPU 短缺之后，全球可能即将面临 CPU 短缺。因为 RL 是当前模型进步的核心路径，而 RL 需要大量 CPU 机器配合 GPU 并行运行。

Ivan Burazin, CEO of Daytona, joined Matt Turck on the MAD Podcast to systematically explain his thinking on AI agent infrastructure. He believes that for the past twenty years everyone has been saying "the end of local hosts" but developers insisted "over my cold dead body." Only with the arrival of agents did this finally change—because agents don't care which machine they run on, they just need a computer of their own.

Burazin breaks down the current agent tech stack into layers: models (the brain), tools (sandboxes, computers, MCP), memory, and orchestration. Memory is the most unsolved problem currently—the best solution uses Markdown files, but models themselves never actually learn smarter during a session; every time is a "new model" rather than a "better model."

He also shared an important prediction: after the GPU shortage, the world may be facing a CPU shortage. Because RL is the core path for current model improvement, and RL requires massive CPU machines running in parallel with GPUs.

### Training Data — "Rebuilding IT From the Ground Up for the AI Age: Serval's Jake Stauch"

Serval CEO Jake Stauch 在 Training Data Podcast 上分享了企业自动化领域的核心洞察：

**"让构建自动化比手动执行更容易"**：如果 reset password 和打开 workflow builder 都能实现，用户永远会选择手动。要让自动化真正普及，必须让构建自动化比手动操作更简单。

**双重 Agent 架构**：Serval 将 agent 分为 admin agent（帮助 IT 管理员构建工具和权限配置）和 helpdesk agent（终端用户对话）。helpdesk agent 可以"疯狂"运行（端用户可以问任何问题），但只能使用 admin 明确发布的工具——实现了灵活性与安全性的平衡。

**模型分工**：OpenAI 模型用于与终端用户交互，Anthropic 模型用于 cogen 自动化（代码生成）。不同场景选最优模型。

**企业 vs AI 原生公司的差异**：不是产品需求不同，而是决策人数不同。AI 原生公司几个人能快速决策，大型企业需要协调多个委员会。

Jake Stauch, CEO of Serval, shared key insights on enterprise automation on the Training Data Podcast:

**"Make building automation easier than doing it manually"**: If resetting a password and opening a workflow builder are both available options, users will always choose manual. To make automation truly pervasive, building automation must be easier than manual execution.

**Dual Agent Architecture**: Serval separates agents into admin agent (helping IT admins build tools and configure permissions) and helpdesk agent (conversing with end users). The helpdesk agent can "run wild" (end users can ask anything), but can only use tools explicitly published by admins—achieving the balance between flexibility and security.

**Model Specialization**: OpenAI models for end-user interaction, Anthropic models for cogen automation (code generation). Choose the best model for each scenario.

**Enterprise vs AI-Native Differences**: Not different product needs, but different number of decision-makers. AI-native companies can decide quickly with a few people; large enterprises need to coordinate multiple committees.
