### Aaron Levie (Box CEO)

Levie wrote a comprehensive post on the FDE (Foundation Model Deployment Engineer) role. He explained why AI agent adoption is much slower than cloud adoption: agents directly impact the workflows that employees participate in, requiring both massive technical work AND change management. Cloud only affected developers and IT, who went to one training session and were done. With agents, every model change means something new is possible or some scaffolding becomes redundant. This is why vendors and partners who've seen hundreds of implementations are often better positioned to help than internal teams alone. The FDE role isn't going away—it's a great path for technical talent, especially early career.

Aaron Levie，Box CEO，深入解析了 FDE（基础模型部署工程师）这个岗位。他解释了为什么 AI Agent 的落地比云计算慢得多：Agent 不仅影响开发者，还直接影响一线员工的工作流程，需要大量的技术工作和变革管理。云计算只影响开发者和 IT，参加一次培训就完成了。但有了 Agent，每次模型更新都意味着能做新的事情，或者某些基础设施变得冗余。这就是为什么有数百次落地经验的供应商或合作伙伴往往比内部团队更有优势。FDE 岗位不会消失——它是技术人才的长期机会，尤其适合早期职业发展。

### AI & I by Every — Inside Stainless: The Developer Tools Startup Anthropic Just Bought for $300 Million

Stainless CEO Alex Rattray joined Dan Shipper to discuss the future of MCP (Model Context Protocol) and how APIs need to evolve for the AI era. Rattray argued that MCP as currently implemented isn't working well—people are handcrafting tools and burning through context windows. His vision for the future: instead of giving models hundreds of tools, the ideal MCP setup is just two tools—one to execute code against an API's SDK, and one to search documentation. The model writes code, runs it on a server near the API, and only returns a minimal result. This solves the context problem and scales much better. Rattray also described how he uses MCP servers internally (Notion, HubSpot, Gong) to query company databases and get summaries. He's building code execution sandboxes where AI can hit APIs, starting with Stripe. On security, he believes OAuth with granular scopes at the API layer is the right approach, not limiting what's exposed through MCP.

Every 的 AI & I 播客——深入了解 Stainless：Anthropic 以 3 亿美元收购的开发者工具公司

Stainless CEO Alex Rattray 加入 Dan Shipper 的节目，讨论 MCP（模型上下文协议）的未来以及 API 如何在 AI 时代演进。Rattray 认为目前实现的 MCP 效果不佳——人们在手写工具、消耗上下文窗口。他对未来的愿景：与其给模型数百个工具，理想的 MCP 设置只有两个工具——一个用来针对 API 的 SDK 执行代码，一个用来搜索文档。模型写代码，在 API 附近的服务器上运行，只返回最小的结果。这解决了上下文问题并能更好地扩展。Rattray 还描述了他如何在内部使用 MCP 服务器（Notion、HubSpot、Gong）来查询公司数据库并获取摘要。他正在构建代码执行沙盒，让 AI 可以调用 API，从 Stripe 开始。在安全方面，他相信在 API 层使用 OAuth 和细粒度权限是正确的方向，而不是限制 MCP 暴露的内容。
