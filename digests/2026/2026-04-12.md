### Anthropic Engineering

**Quantifying infrastructure noise in agentic coding evals**

Agentic 编程评估（如 Terminal-Bench 2.0 和 SWE-bench）的分数差距可能更多反映的是基础设施配置而非模型真实能力差距。Anthropic 的实验发现：严格资源限制（1x）vs 完全不限制（uncapped）之间，分数差距高达 **6 个百分点**（p < 0.01），主要驱动力是 infra 错误率从 5.8% 降至 0.5%。达到 3x 资源配置后，额外增加资源开始真正帮助模型解决更难题——这意味着资源限制改变了评估本身测量的内容。

Benchmark scores on agentic coding evals like Terminal-Bench 2.0 and SWE-bench may reflect infrastructure configuration more than genuine model capability differences. Anthropic found a **6 percentage point** gap (p < 0.01) between strict resource enforcement (1x) and uncapped resources, driven primarily by infra error rates dropping from 5.8% to 0.5%. Beyond 3x resource headroom, additional resources start actively helping the model solve harder problems—meaning resource limits change what the eval actually measures.

关键建议：排行榜上 3 分以内的差距不值得盲目解读；资源规格应被当作一等实验变量；benchmark 应同时注明 guaranteed allocation 和 hard kill threshold 两个参数，而非单一 pinned 值。

Key recommendation: Score differences within 3 percentage points on agentic leaderboards deserve skepticism; resource specs should be treated as first-class experimental variables; benchmarks should specify both guaranteed allocation and hard kill thresholds, not a single pinned value.

### Anthropic Engineering

**Claude Code auto mode: a safer way to skip permissions**

Auto Mode 是介于"每次人工审批"和"完全跳过权限"之间的中间方案，用两层防御替代全有/全无的权限模型。Input 层：Prompt Injection 探测——在工具输出进入 context 前扫描，发现恶意指令注入时插入警告。Output 层：Transcript Classifier（在 Sonnet 4.6 上运行），分两阶段判断——快速单 token 过滤（err toward blocking）+ Chain-of-Thought 推理（仅在第一层 flag 时触发）。

Auto Mode sits between manual approval and skipping permissions entirely. Input layer: prompt-injection probe that scans tool outputs before they enter context, injecting a warning alongside suspicious content. Output layer: transcript classifier running on Sonnet 4.6, with a two-stage pipeline—a fast single-token filter (tuned to block) followed by chain-of-thought reasoning only when flagged.

实测数据：真实流量（n=10,000）FPR 从 Stage 1 的 8.5% 降至两阶段后的 0.4%；真实 overeager 行为（n=52）FNR 为 17%；合成数据泄露测试（n=1,000）FNR 为 5.7%。设计亮点：Strip 掉 Claude 自己的回复和工具输出，只看 user messages + tool calls，防止 Claude"用话术说服分类器"。

Results: real traffic (n=10,000) FPR drops from 8.5% to 0.4%; real overeager actions (n=52) FNR is 17%; synthetic exfiltration (n=1,000) FNR is 5.7%. Design highlight: Claude's own responses and tool outputs are stripped so it can't "talk the classifier into a bad call."
