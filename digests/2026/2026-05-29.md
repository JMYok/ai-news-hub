### Anthropic Engineering: Claude Code Quality Incident — A Postmortem

**The Takeaway:** Anthropic openly disclosed the root cause of the quality regression reports over the past month — three independent issues, all now fixed. Their honesty is itself a product strategy.

Anthropic's engineering team published a thorough postmortem on the quality reports they received over the past month. Three separate changes affected Claude Code, the Claude Agent SDK, and Claude Cowork:

1. **Default reasoning effort changed from high to medium** (March 4) — to reduce latency. User feedback caused a revert on April 7.
2. **Cache clearing bug** (March 26) — a programming error caused the thinking history to be cleared on every turn after session resumption, making Claude appear forgetful and repetitive. Fixed April 10.
3. **System prompt change to reduce verbosity** (April 16) — "keep responses under 100 words unless detail is required" interacted badly with other prompt changes and degraded coding quality. Reverted April 20.

Key metrics: After the full pipeline, FPR dropped to 0.4%, but FNR is 17%. The official honest assessment: "If you're running dangerous commands, this is a substantial improvement. If you're doing careful manual review, this is a regression." Auto mode targets the first group.

One notable finding: when back-testing the offending code against Opus 4.7 with full repository context, Opus 4.7 identified the bug — Opus 4.6 did not. The model itself has become capable of code review.

**Anthropic Engineering 发布了 Claude Code 质量下降问题的完整 postmortem——三个独立问题全部已修复，官方坦诚公布根因。** 三个问题：①默认推理强度从 high 改为 medium 后回滚；②缓存清理 bug 导致会话恢复后推理历史每次都被清空；③"回复控制在 100 字以内"导致编码质量下降后回滚。完整 pipeline FPR 降至 0.4%，FNR 为 17%。有趣细节：Opus 4.7 能找到这个 bug，Opus 4.6 不能——模型本身已具备代码审查能力。

### Anthropic Engineering: Scaling Managed Agents — Decoupling the Brain from the Hands

**The Takeaway:** Anthropic's new Managed Agents architecture borrows a classic OS design pattern — virtualize the components so each can fail and be replaced independently. This is how you build agents for "programs as yet unthought of."

The core problem: if you put the agent harness, session, and sandbox all in one container, that container becomes a "pet" — a named individual you can't afford to lose. They needed "cattle."

The solution: decouple three components into independent interfaces:

- **Session** — append-only log of everything that happened, lives outside Claude's context window. The interface `getEvents()` lets the brain interrogate context by positional slices of the event stream.
- **Harness** — the loop that calls Claude and routes tool calls. Nothing in the harness needs to survive a crash. When it fails, a new one boots with `wake(sessionId)`, reads the event log, and resumes.
- **Sandbox** — execution environment where Claude runs code and edits files. Called via `execute(name, input) → string`. If it dies, the harness catches it as a tool-call error and Claude can retry with a new container.

Security boundary: tokens are never reachable from the sandbox where Claude's generated code runs. Git credentials are bundled during sandbox initialization; MCP OAuth tokens live in a vault outside the sandbox.

Performance result: after decoupling, p50 TTFT dropped ~60% and p95 dropped over 90%.

**Anthropic Engineering 发布了 Managed Agents 的架构设计——将 brain、session、sandbox 解耦为独立接口，灵感来自操作系统虚拟化。** 核心思想：组件可以独立失败和替换，session 是 append-only 日志，harness 是无状态循环，sandbox 通过 execute 接口调用。结果：p50 TTFT 下降约 60%，p95 下降超过 90%。安全边界：token 永不进入 sandbox 运行环境。

https://www.anthropic.com/engineering/managed-agents

### AI & I by Every: We Automated Everything With AI and Tripled Our Headcount

**The Takeaway:** Every CEO Dan Shipper's core argument: AI makes yesterday's expert competence cheap, which creates a glut of "good enough" work — and that actually increases demand for experts who can make it actually good. "If you ride the models, you're going to be okay."

Dan Shipper, CEO of Every, published an 8,000-word piece called "After Automation" and sat down with Every's COO Brandon Kan to work through the reasoning.

The paradox: Every went from 4 people to 30 people since GPT-3, and they're hiring more. They use Claude Code and Codex constantly — as AI-native as it gets. Yet there's more human work to do than ever.

The core insight: AI makes yesterday's expert competence cheap. Anyone can now use a prompt to build an app, write a report, or create a design. But everything produced looks similar and isn't quite right for the actual situation. This creates a glut of "close but not quite" work — and that actually increases demand for experts who can evaluate, refine, and ship it.

The "Achilles and the tortoise" framing: You prompt AI, it blows your mind, you feel inadequate — and then it stops working and looks back at you asking "what should I do next?" Until we have AGI (and probably long after), AI will always be asking humans for direction.

On benchmarks: models saturate a benchmark, then it's easy to find a new frame that's slightly larger and zero it out. Progress is exponential, but that doesn't mean it's equivalent to human capabilities. Anything you can articulate, a model can hill climb on — but there's stuff you do that can't be articulated, and that's the permanent gap.

On AGI: a good definition is an agent valuable enough to run all the time, generating tokens and doing tasks without you ever having to prompt it. Will it happen? Probably. Is it a good thing? Yes — because humans still decide what matters, and what matters keeps changing (especially as AI changes the world).

The counter to the ClickUp layoffs narrative: the company was poorly managed and had bloat. AI is involved, but the real story is reorganizing for a changed strategy — not "AI took people's jobs."

**Every CEO Dan Shipper 的核心论点：AI 让昨天的专家能力变得廉价，由此产生大量"差不多好"的内容——这反而增加了对真正专家的需求。"如果你跟上这些模型，你就没事。"** Every 从 4 人增长到 30 人，Agent 和人类员工共存，但工作量反而增加。核心洞察：AI 使专家能力民主化 → 产生大量相似但不够准确的内容 → 需要专家来把关和提升。AI 再强，也永远需要人类来定义"什么是有价值的"。
