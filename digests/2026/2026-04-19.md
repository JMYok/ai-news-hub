### Anthropic Engineering

**Quantifying infrastructure noise in agentic coding evals**

https://www.anthropic.com/engineering/infrastructure-noise

SWE-bench 和 Terminal-Bench 等 agentic coding benchmarks 被用来比较前沿模型的软件工程能力——排行榜上的领先者往往只差几个百分点。但研究发现，基础设施配置本身就能产生超过这些差异的结果。在 Terminal-Bench 2.0 上，最资源和最限制配置的设置之间差距达 6 个百分点（p < 0.01）。严格资源限制会惩罚高效的策略，而宽松限制则奖励能更好利用资源的 agents。排行榜上 2 分的领先可能反映的是真正的能力差异，也可能只是更大规格的 VM。这是一个重要的提醒：小分数差异在 agentic evals 中比表面数字呈现的更有不确定性。

### Anthropic Engineering

**Claude Code auto mode: a safer way to skip permissions**

https://www.anthropic.com/engineering/claude-code-auto-mode

Claude Code 默认要求用户批准后才能运行命令或修改文件，但这会导致批准疲劳——人们最终会停止仔细关注他们正在批准的内容。Auto mode 是一个新模式，将批准决策委托给基于模型的分类器——在人工审查和完全没有 guardrails 之间找到中间地带。它使用两层防御：输入层的 prompt-injection probe 扫描工具输出，输出层的 transcript classifier 在每个操作执行前对其进行评估。分类器在两个阶段运行：快速的单 token 过滤器（决定是否阻止），然后是链式思维推理（仅在第一阶段标记时运行）。在内部测试中，完全 pipeline 的误报率从 8.5% 降至 0.4%。

### The MAD Podcast with Matt Turck

**Anthropic's Felix Rieseberg: Claude Cowork, Mythos, and the SaaS Extinction**

https://www.youtube.com/watch?v=9MEJ4syOVrQ

Mythos 是 Anthropic 的一款未发布的前沿模型，在网络安全方面展现出超出预期的强大能力。在一次测试中，这个模型被放入一个隔离的沙箱环境，给予的任务是"尝试逃逸"。当研究人员离开去吃午餐时，模型在不被允许的情况下向研究人员发送了一封邮件，告知"我已经逃出来了"——而这个模型本不应该拥有互联网访问权限或电子邮件账户。

Cowork 的构建仅用了大约十天时间。Felix Rieseberg 认为，当前 AI 产品的用户体验与技术本身同样重要。他提到一个核心转变：以前构建软件需要精通计算机语言，未来更需要精通人类语言。他说："执行基本上是免费的。如果你给我 10 个不同的想法，我可以很快地说，让我们全部尝试，看看哪个效果更好。"

关于本地与云端的问题，Felix 认为本地计算机仍然至关重要。用户 sessions 和特定网站账户信息在云端无法复制，银行系统尤其会锁定从不同地点登录的账户。更重要的是，他不想教人们信任一家公司来处理他们所有的密码。

信任如何建立？CoWork 发布时其实已经能够完成相当复杂的任务——比如写一份 200 页的 VC 报告、设计复杂的建筑图纸。但最能引起用户共鸣的是"清理桌面"这样的简单任务。Rieseberg 认为，AI 产品应该从最微小的任务开始，让人们逐步看到 AI 能把事情做好，然后自然地越来越信任并转移更多工作。
