### Aaron Levie | CEO @ Box

**English:**

Aaron Levie argues that as agents become the biggest users of software, **all software must be available in a headless fashion** — agents won't use your UI, they'll talk to your APIs. He outlines three emerging pricing models:

1. **Seats for humans + API usage**: Humans pay per seat with bundled API calls on their behalf. When you buy a seat, it comes with API access your agent can use through you. Most software (including Box) will integrate seamlessly with ChatGPT, Codex, Claude, Gemini, Cursor, Copilot, Perplexity, etc.

2. **Agent "seats" for stateful work**: When an agent has its own workspace, stores its own data, and needs different permissions, it may look like another "user" in the system. But pricing like a human seat is nearly impossible — one company might use 1 agent, another 1,000.

3. **Consumption model for headless use**: Above seat allotments, or when an agent acts independently, usage-based pricing kicks in. Some cases need new API types representing what an agent does in one go — closer to an **outcome** than a series of API calls.

> *"The growth of this usage pattern is effectively unbounded. Every platform that goes headless will need to adopt a model like this. Some may fight it initially, but it's inevitable."*

🔗 https://x.com/levie/status/2050051426446152159

**中文：**

Aaron Levie 认为，随着 Agent 成为软件的最大用户，**所有软件都必须以头部化（headless）方式提供**——Agent 不会使用你的 UI，它们直接调用你的 API。他提出三种新兴定价模式：

1. **人类按 seat 付费 + API 用量**：人类按席位付费，附带 Agent 可代表其使用的 API 调用量。大多数软件（包括 Box）将与 ChatGPT、Codex、Claude、Gemini、Cursor、Copilot、Perplexity 等深度集成。

2. **Agent"席位"适用于有状态工作**：当 Agent 有自己工作区、存储独立数据、需要不同权限时，它表现为系统中的另一个"用户"。但按人类 seat 定价几乎不可能——一家公司可能用 1 个 Agent，另一家可能用 1000 个。

3. **头部化使用的消费模式**：超出 seat 配额或 Agent 独立行动时，按用量计费。某些场景需要新型 API——代表 Agent 一次完成的工作，接近于**一个结果**而非一系列 API 调用。

> *"这种使用模式的增长实际上是无上限的。每个走头部化路线的平台都需要采用类似的模式。有些最初会抗拒，但这是必然的。"*

### Ryo Lu | Design @ Cursor

**English:**

Ryo Lu shared a deep philosophical thread on what it means to build for **universality without sacrificing opinion**. His key argument: "no opinion is itself a strong opinion." When you decide what concepts exist, what's visible, what composes, what extends, what hides — you've already expressed a worldview. Building for universality means saying something very specific: core concepts should be few, durable, and flexible.

He argues that **pure customer-centricity falls short** — user feedback tells you where friction is, but rarely what the underlying system should be. If you only follow direct user demand, you converge on local maxima: fragmented features, narrow tools, products shaped around current habits rather than enduring concepts.

> *"Great systems don't start by multiplying products. They start by reducing concepts to their essence — until the primitives become clear. Simple at the core. Open at the edges."*

🔗 https://x.com/ryolu_/status/2049866003287576978

**中文：**

Ryo Lu 分享了一个深刻的哲学推文，探讨什么是真正的**通用性而不牺牲观点表达**。他的核心论点是："没有立场本身就是一个强烈的立场。"当你决定存在哪些概念、什么可见、什么可组合、什么可扩展、什么隐藏——你已经表达了一种世界观。构建通用性意味着说出非常具体的东西：核心概念应该少而精、持久且灵活。

他认为**纯粹的客户中心主义是远远不够的**——用户反馈告诉你摩擦在哪里，但很少告诉你底层系统应该是什么。如果只跟随直接用户需求，你会收敛到局部最优：功能碎片化、工具狭窄、产品围绕当前习惯而非持久概念构建。

> *"伟大的系统不是从增加产品开始。它们从将概念精简到本质开始——直到原语变得清晰。核心简单，边缘开放。"*

### Claude Blog: Redesigning Claude Code on desktop for parallel agents

**English:**

Claude Code 发布了桌面版重大重设计，核心变化：**并行 Agent 工作流**。新设计将所有活动和最近会话集中在一个侧边栏，支持跨多个代码仓库同时启动任务、结果到达后切换，以及在任务中途打开副对话（⌘ + ;）分支出去提问而不影响主线程。
