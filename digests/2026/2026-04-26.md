### No Priors: SAP CTO Philipp Herzig 谈企业 AI 转型 / SAP CTO Philipp Herzig on Enterprise AI Transformation

**English:**

The biggest lesson from SAP's AI transformation journey: cool demos ≠ real adoption. The gap between the "innovation race" and the "outcome race" is actually widening — and the only way to close it is deep integration with actual business data and processes, not more flashy model releases.

SAP's CTO Philipp Herzig brings a rare combination of technical depth and business pragmatism. With 400,000 enterprise customers running end-to-end operations on SAP — finance, HR, supply chain, manufacturing — he's seeing first-hand where AI delivers and where it stalls. His key argument: most AI failures aren't intelligence failures, they're **tool-use failures at scale**. Building a POC with 10 documents is trivial. Running reliably across 20,000 APIs, across 90 countries, with different payroll rules and tax jurisdictions — that's the real engineering challenge.

SAP's internal data reveals that the biggest bottleneck isn't the AI itself — it's teaching the AI to do the right thing at scale. MCP servers break past 100 APIs due to context bloat. Joule for Consulting already shows 30% effort reduction for consultants, but scaling that across hundreds of different enterprise landscapes is an unsolved problem. His contrarian take: LLMs are fundamentally not suited for predictive/tabular tasks — SAP developed RPT (Relational Pretrained Transformers) specifically for classification, regression, and time-series prediction, where traditional ML models still outperform transformers.

### Anthropic Engineering: Scaling Managed Agents — Decoupling the Brain from the Hands

**English:**

Anthropic's managed agents architecture solved a fundamental problem: how to design a system that accommodates "programs as yet unthought of." Their solution — decoupling the brain (Claude + harness) from the hands (sandboxes/tools) and the session (append-only event log) — mirrors how operating systems virtualized hardware into stable abstractions.

The core insight is the "pets vs. cattle" reframe: when the harness, session, and sandbox all lived in one container, losing the container meant losing the session. The container became a pet that had to be nursed back to health. After decoupling, each component is cattle — if the sandbox dies, the harness catches it as a tool-call error and Claude retries with a fresh container. No more nursing.

Performance results were striking: P50 TTFT dropped ~60% and P95 TTFT dropped over 90% after moving the harness out of the container. The reason: containers were being initialized for every session, even ones that never needed the sandbox. Now containers are provisioned on-demand via tool call, and inference can start immediately using events already in the session log.

Security architecture is equally thoughtful: git tokens are injected during sandbox initialization and wired into the local git remote — the agent code never handles tokens. OAuth tokens live in an external vault, accessed via a dedicated proxy that fetches session-linked credentials. This is structural defense against prompt injection, not just policy.

The session itself acts as an external context object: it's append-only, queryable via `getEvents()` by positional slice, supports rewind and replay, and lives outside Claude's context window. Irreversible context trimming (the standard solution to context overflow) is replaced by durable, recoverable context management.

Source: https://www.anthropic.com/engineering/managed-agents

---

**中文:**

Anthropic 的 Managed Agents 架构解决了一个根本问题：如何设计一个能容纳"尚不可预见的程序"的系统。他们的方案——将大脑（Claude + harness）与手脚（sandbox/tools）和 session（append-only 事件日志）解耦——与操作系统将硬件虚拟化为稳定抽象的思路一脉相承。

核心洞察是"宠物 vs 牛群"的重新诠释：当 harness、session 和 sandbox 都在同一容器中时，容器挂了 = session 丢了，容器成了需要精心呵护的宠物。解耦后，每个组件都是牛群——sandbox 挂了，harness 将其捕获为 tool-call 错误，Claude 重试并启动新的 container，无需修复旧容器。

性能结果惊人：harness 移出容器后，P50 TTFT 下降约 60%，P95 TTFT 下降超过 90%。原因是：之前每个 session 都要初始化 container，即使它根本不需要 sandbox。现在 container 按需通过 tool call 启动，推理可以立即使用 session log 中已有的 events。

安全架构同样精妙：git token 在 sandbox 初始化时注入，直接写入本地 git remote，agent 代码永远接触不到 token。OAuth token 存外部 vault，通过专用 proxy 按 session 关联的 credentials 获取。这是针对 prompt injection 的结构化防御，而非仅靠策略。

session 本身充当外部 context 对象：append-only、可通过 `getEvents()` 按位置切片查询、支持 rewind 和 replay、不受 Claude context window 限制。Context 溢出时标准方案（不可逆的 context  trimming）被持久化、可恢复的 context 管理所替代。
