### Peter Yang (Product at Roblox)

Peter Yang shared his top 5 takeaways from Alex Albert (Anthropic Research PM) on how Anthropic is building the next Claude model:

1. **Model and harness are coupled** — The same model gives different responses depending on where it runs (Claude, Cowork, Claude Code). Research PMs must think through performance across all surfaces.
2. **Claude is starting to dream** — When idle, agents review their own memories, find contradictions, and prune them. Inspired by how sleep helps humans process memory.
3. **Focus evals on real user problems** — The team uses Claude to cluster the firehose of user feedback into top themes, then generates synthetic versions of each problem for eval. Even a few dozen well-written test cases can produce an effective eval.
4. **Full-time researchers think about Claude's consciousness** — Anthropic has people whose job is to think about what it means for Claude to be a conscious actor. The question is taken seriously as agents take on more autonomous work.
5. **Anthropic's writing culture builds context** — Every written word becomes context Claude can pull later. "Get things written down, make them accessible to Claude, because that's just more context that it has."

Peter Yang 分享了他从 Anthropic 研究 PM Alex Albert 那里的五大收获：

1. **模型和 harness 是耦合的** — 同样的模型在 Claude、Cowork、Claude Code 不同环境下表现不同。研究 PM 必须考虑模型在所有产品面的表现。
2. **Claude 开始做梦了** — Agent 空闲时会回顾自己的记忆，发现矛盾并修剪。灵感来自人类睡眠时处理记忆的方式。
3. **Evals 聚焦真实用户问题** — 团队用 Claude 将海量用户反馈聚类为主题，然后为每个问题生成合成版本做测试用例。几十个精心设计的测试用例就能产生有效的 eval。
4. **有全职研究员思考 Claude 的意识** — Anthropic 有人专门思考 Claude 成为有意识的行为者意味着什么。随着 Agent 承担更多自主工作，这个问题被认真对待。
5. **Anthropic 的写作文化构建 context** — 每个写下的字都成为 Claude 可以调用的 context。"写下来，让 Claude 能访问，因为这都是它可以用的 context。"

### Thariq (Claude Code @ Anthropic)

This gives the model a good out to make decisions but keep you informed.

Thariq 分享了他如何让长时间运行的 Agent 保持同步：规范中总有模糊和未知，所以他维护一个 implementation-notes.html 文件，记录实现与规范的偏离——包括设计决策、偏离原因、权衡考量以及待确认问题。这给了模型一个出口：可以自己做决定，但同时让你知情。

### Anthropic Engineering

**An update on recent Claude Code quality reports**
https://www.anthropic.com/engineering/april-23-postmortem

Anthropic published a detailed postmortem on reports that Claude's responses had worsened for some users. Three separate changes affected Claude Code, Claude Agent SDK, and Claude Cowork:

1. **Default reasoning effort change** (March 4) — Changed default from "high" to "medium" to reduce long latency. Reverted April 7 after users said they'd prefer higher intelligence and opt into lower effort for simple tasks.

2. **Cache optimization bug** (March 26) — A bug in a "clear thinking" optimization caused it to keep happening every turn for the rest of the session instead of just once, making Claude seem forgetful and repetitive. Fixed April 10.

3. **Verbosity reduction system prompt** (April 16) — Added "Length limits: keep text between tool calls to ≤25 words. Keep final responses to ≤100 words" which, combined with other prompt changes, hurt coding quality. Reverted April 20.

All three issues resolved as of April 20 (v2.1.116). Usage limits reset for all subscribers. Going forward: larger share of internal staff will use exact public build, tighter controls on system prompt changes, broader eval suites for per-model prompt changes, and gradual rollouts.

Anthropic 发布了关于近期 Claude Code 质量下降报告的详细复盘。三个独立变更影响了 Claude Code、Claude Agent SDK 和 Claude Cowork：

1. **默认推理强度变更**（3 月 4 日）— 将默认值从"high"改为"medium"以降低延迟。4 月 7 日用户反馈后回滚，用户表示宁愿默认更高智能、在简单任务时自行选择更低强度。

2. **缓存优化 bug**（3 月 26 日）— "清除 thinking"优化实现中的 bug 导致它在会话剩余的每个 turn 都持续执行，而非仅一次，造成 Claude 看起来健忘和重复。4 月 10 日修复。

3. **缩减长度的系统提示词**（4 月 16 日）— 添加"长度限制：tool calls 之间 ≤25 词，最终回复 ≤100 词"，与其他提示词变更组合后损伤了编码质量。4 月 20 日回滚。

所有三个问题在 4 月 20 日（v2.1.116）已解决。所有订阅用户的用量限制已重置。后续改进：更大比例内部员工使用公开版本、收紧系统提示词变更管控、每个模型提示词变更跑更广泛 eval 套件、渐进式发布。

### AI & I by Every — "The Secrets of Claude's Platform From the Team Who Built It"

**Guests**: Angela (Head of Product, Cloud Platform) and Caitlin (Head of Engineering, Cloud Platform) from Anthropic

**The Takeaway**: The biggest barrier to agent success isn't intelligence—it's production infrastructure. Anthropic built Cloud Managed Agents because even their own teams kept hitting the same wall: spinning up infrastructure, handling session persistence, managing secure sandboxes. The platform handles all of that so developers can focus on outcomes.

Key insights:

- **Harness and model are path-dependent** — Small decisions about how to do requests/responses or tool calls end up changing the trajectory of what the model is good at. Labs taking different approaches now; the harness plus model become a paired unit rather than a generic harness with hot-swappable models.

- **Infrastructure is the wall everyone hits** — People think harness engineering is the hard part, but productionizing is where everyone gets stuck. Secure sandboxing, session persistence, dealing with dead connections. This was the big inspiration for Cloud Managed Agents.

- **Multi-agent architectures need team-level abstraction** — Individual productivity with AI is relatively straightforward; team orientation is where complexity explodes. Vercel uses this as an "AI software factory" internally to transform every company process.

- **Agents dream when idle** — Claude reviews memories, finds contradictions, and prunes them during downtime, inspired by how sleep helps humans process memory.

- **Best practice: someone owns each agent** — Without a human responsible, agents get stale quickly. The best companies (Stripe's Minions, Ramp) have dedicated developer productivity teams maintaining these.

- **One year from now**: Claude will understand itself well enough to figure out what model to use, how to spin up sub-agents, and even write itself on the fly. The user just specifies outcome and budget.

Anthropic 平台产品负责人 Angela 和工程负责人 Caitlin 分享：

**核心结论**：Agent 成功的最大障碍不是智能——是生产基础设施。Anthropic 之所以构建 Cloud Managed Agents，是因为他们自己的团队也一直撞同一堵墙：架设基础设施、处理 session 持久化、管理安全沙盒。平台解决了这些，让开发者专注结果。

关键洞察：

- **Harness 和模型是路径依赖的** — 请求/响应方式或 tool calls 的小决定最终改变模型擅长方向的轨迹。各实验室现在走不同路线；harness + model 成为配对单元，而非通用 harness 加可热插拔模型。

- **基础设施是每个人都会撞的墙** — 大家以为 harness 工程是难点，但生产化才是卡住的地方。安全沙盒、session 持久化、连接断开处理。这才是 Cloud Managed Agents 诞生的重要原因。

- **多 Agent 架构需要团队级抽象** — 个人层面的 AI 生产力相对简单；到了团队层面复杂度爆炸。Vercel 将此作为内部"AI 软件工厂"来改造公司每个流程。

- **Agent 空闲时会做梦** — Claude 在停机期间回顾记忆、发现矛盾并修剪，灵感来自人类睡眠时处理记忆的方式。

- **最佳实践：每个 Agent 有人负责** — 没有负责人，Agent 很快就会过时。最好的公司（Stripe 的 Minions、Ramp）有专职开发者效能团队来维护。

- **一年后**：Claude 会足够了解自己，能自行判断用什么模型、如何启动 sub-agent、甚至动态重写自己。用户只需指定 outcome 和 budget。
