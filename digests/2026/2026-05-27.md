### The MAD Podcast with Matt Turck — Why AWS and Azure Cannot Run Autonomous AI (Ivan Burazin, CEO of Daytona)

**Sandbox 是 AI Agent 的"计算机"——每个 Agent 都需要自己专属的计算环境。**

Daytona CEO Ivan Burazin 在 MAD Podcast 上分享了一个核心洞察：**AI Agent 本质上是"数字雇员"，需要像人类一样拥有自己的计算机才能高效工作。** 这不是夸张——当你让 Agent 访问银行账户时，你需要给它自己的机器、自己的账号、甚至自己的手机号（用于 2FA 验证）。Agent 不再只是调用 API，而是需要完整的计算机来完成任务。

Burazin 提出了一个重要概念：**Stateful（持久化）vs Stateless（无状态）**。传统云服务（AWS、Azure）基于无状态架构设计，适合部署 App，但不适合需要持续运行、拥有记忆、与真实世界交互的 AI Agent。Sandbox 本质上是为 Agent 重新设计的"可组合计算机"。

在 Agent 技术栈中，Burazin 认为：**Models（模型）= 大脑，Tools（工具）= 手，Sandbox（沙盒）= 身体，Memory（记忆）= 经验，Orchestration（编排）= 管理。** 当前最不成熟的环节是 Memory——模型不会从错误中学习，只能通过上下文记住，而不能真正积累经验。

他还提到一个被忽视的趋势：**CPU 短缺即将到来。** 随着 RL（强化学习）成为模型训练主流，大规模需要 CPU 机器的 Sandbox 需求激增，可能引发比 GPU 短缺更严重的问题。

**"Every agent will need at least one sandbox, sometimes more."**

Daytona CEO Ivan Burazin shared the core insight on the MAD Podcast: **AI agents are "digital knowledge workers" that need their own computers — not just APIs or tools, but full machines with their own accounts, phone numbers for 2FA, and isolated environments.** He argues every agent needs at least one sandbox, sometimes more.

Burazin distinguishes Stateful vs Stateless: traditional clouds (AWS, Azure) are built stateless — great for deploying apps, but wrong for AI agents that need persistent state, memory, and real-world interaction. Sandboxes are "composable computers for AI agents" — built from the ground up for this new workload.

On the agent stack, Burazin maps: **Models = brain, Tools = hands, Sandbox = body, Memory = experience, Orchestration = management.** The least solved piece today is Memory — models don't actually learn from mistakes, they only remember contextually.

He also flagged an underappreciated trend: **a CPU shortage is coming.** As RL (reinforcement learning) becomes the dominant training paradigm, massive demand for CPU-based sandbox machines could create shortages worse than the GPU crunch.
